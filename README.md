# Brancher

Бесплатный кроссплатформенный Git-клиент с открытым кодом: граф истории, работа с рабочей
копией до уровня строк и все повседневные операции Git без терминала. Референс поведения —
[SourceGit](https://github.com/sourcegit-scm/sourcegit), код пишется с нуля на Rust.

Спецификация: «Спецификация: десктопный Git-клиент (аналог SourceGit)» (Claude Docs).

## Стек

Rust · eframe/egui 0.36 · компоненты из shadcn_egui (перенесены в `crates/widgets`) ·
установленный `git` (2.25.1+) как единственный источник истины.

## Структура (раздел 3 спецификации)

| Крейт | Пакет | Содержимое |
|---|---|---|
| `crates/app` | `brancher` (bin) | `main`, окно eframe, цикл кадра, helper-режим (заготовка) |
| `crates/ui` | `brancher-ui` | Стартовая страница, вкладки, ветки, история, изменения и коммит |
| `crates/widgets` | `widgets` | Код shadcn_egui @ `7425c3f` (MIT), доработки — здесь, см. `UPSTREAM.md` |
| `crates/core` | `brancher-core` | Модели, `AppState`/`RepoState`, `Action` → `reduce` → `Effect`; без I/O |
| `crates/git` | `brancher-git` | `Runner` (без shell, с отменой), аргументы и парсеры status/log/refs |
| `crates/services` | `brancher-services` | Очередь задач на репозиторий, результаты в UI через канал + repaint |

Пакеты называются `brancher-*`: имя `core` занято встроенным крейтом Rust.

## Запуск

```sh
cargo run                       # стартовая страница
cargo run -- /path/to/repo      # сразу открыть репозиторий
cargo run -p widgets --example gallery   # галерея компонентов
```

## Тесты

```sh
cargo test -p brancher-core -p brancher-git -p brancher-services   # без окна, нужен только git
cargo test --workspace                                             # + snapshot-тесты widgets (wgpu)
```

Слои `core` и `git` зависят только от std. Сторонние крейты из раздела 3 добавляются вместе
с функциями, которым они нужны: syntect, notify и serde уже в `services`, keyring — дальше.

## Что уже работает

- Открытие репозитория по пути, клонирование с прогрессом и отменой, вкладки (Ctrl+W, Ctrl+Tab), F5 — обновить.
- Статус (porcelain v2, переименования, конфликты, не-ASCII пути), ветки/remotes/теги с ↑↓.
- История с виртуальной прокруткой (до 20 000 коммитов, `--all --date-order`).
- Stage/unstage файлов (двойной клик, «Stage all»), commit и amend (Ctrl+Enter).
- Граф коммитов (раскладка в фоне) и diff коммита, индекса и рабочей копии.
- Частичный stage/unstage: ханк целиком или выбранные строки (клик, Shift/Ctrl+клик, S).
- Discard строк и ханков в рабочей копии — с подтверждением.
- Diff в одну или две колонки (side-by-side).
- Подсветка синтаксиса в diff (syntect, считается в фоне, цвета под светлую и тёмную тему).
- Автообновление при изменениях снаружи (редактор, терминал): notify, пачки событий,
  игнорируемые git файлы (сборка, `node_modules`) не вызывают обновления.
- Вкладки, недавние репозитории, тема и режим diff сохраняются между запусками
  (`state.json` в папке настроек ОС, путь можно переопределить `BRANCHER_CONFIG_DIR`).
- Ветки: переключение (двойной клик, в том числе на remote-ветку с созданием локальной),
  создание от ветки, тега или коммита, удаление с подтверждением — через контекстные меню.
- Fetch (все remotes, с prune), pull (только fast-forward) и push (с `-u`, если у ветки нет
  upstream) с прогрессом и отменой; кнопки показывают ↓/↑ относительно upstream.
- Remotes: ветки сгруппированы по remote; добавить (+), переименовать и сменить URL, fetch
  одного remote, удалить (с подтверждением). Push работает и в remote, где ещё не было fetch.
- Merge и rebase из меню ветки (rebase — с подтверждением). При конфликтах панель изменений
  показывает, что идёт операция и сколько конфликтов осталось; по правому клику на файле можно
  взять версию одной из сторон или отметить файл решённым, затем «Продолжить» или «Прервать».
  Diff файла с конфликтом показывает рабочую копию против HEAD с маркерами.
- Interactive rebase: «Interactive rebase отсюда…» в меню коммита открывает план от этого коммита
  до HEAD: порядок стрелками, pick / reword (с новым сообщением) / squash / fixup / drop.
  Конфликты разрешаются так же, как при обычном rebase.
- Сравнение веток: «Сравнить с …» в меню ветки или тега показывает коммиты, которые есть только
  с одной стороны, и diff от общего предка (то, что принесёт слияние), с кнопкой «Слить».
- Blame и история файла: правый клик по файлу в списке изменений или по заголовку файла в diff.
  Blame показывает автора, коммит и дату каждой строки (в коммите diff или в рабочей копии),
  история — коммиты файла с учётом переименований; клик открывает diff коммита.
- Поиск по истории (Ctrl+F): слова ищутся в заголовке и авторе, слово из 4+ hex-символов — ещё
  и как начало SHA; фильтр «Только текущая ветка» оставляет коммиты, достижимые из HEAD.
- Теги: создать на коммите (с сообщением — аннотированный), удалить, отправить в remote.
  Cherry-pick и revert из меню коммита; конфликты разрешаются так же, как у merge.
- Stash: спрятать изменения (с сообщением, при желании вместе с неотслеживаемыми файлами),
  список записей под тегами, diff записи по клику, применить, применить и удалить, удалить
  с подтверждением. Коммиты stash в граф истории не попадают.
- Логин и пароль для HTTPS и пароль ключа SSH спрашиваются в диалоге: Brancher сам служит
  `GIT_ASKPASS`/`SSH_ASKPASS` и передаёт ответ git через localhost с одноразовым токеном.
- Ошибки git показываются со stderr и кнопкой «Копировать».
